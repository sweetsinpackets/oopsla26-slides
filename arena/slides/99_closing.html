Backup: Cycles Deallocated in Bulk

the cycle inside one arena, now in a scoped arena


  {
    val a = new Ref(()) !!scoped!!
    val c1, c2, c3 = new Ref(f) at a
    c1 := (x: Int) => (!c2)(x)
    c2 := (x: Int) => (!c3)(x)
    c3 := (x: Int) => (!c1)(x)
  }   // !!{a, c1, c2, c3} deallocated together!!
Reference counting alone never reclaims this. no count in a cycle ever reaches zero
A scoped arena deallocates all of it. and no value that outlives the block refers into it

Backup: Why Coarse Tracking Is Still Sound

Coarseness never crosses an arena boundary. two arenas are two locations, and disjointness between them is exactly as before
Within an arena, there is nothing to lose. members share a lifetime by construction, so per-cell lifetime information would say nothing new
What you do give up: separation inside one arena. two cells in the same arena never look disjoint, so put things you want to parallelize in different arenas

Backup: Limitations

  • Flow-insensitive. Deallocation is guaranteed for scoped arenas at scope exit; not for arbitrary arenas, and not mid-scope.
  • Granularity is coarse by design. No separation between two cells of one arena.
  • Escaping requires term-level coercions in this calculus; doing it by subtyping is the PLDI'26 paper.
  • No object encoding yet. Cyclic store structures, yes; full cyclic data structures, future work.
