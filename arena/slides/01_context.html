Arenas: Grouped Allocation and Bulk Deallocation


  val a = Arena()
  val x = a.alloc(...)
  val y = a.alloc(...)
  ...
  a.dealloc()  // x, y, ...: deallocated together
Web servers: one arena per request
Compilers: one arena per function

Lifetimes: Lexical and Non-Lexical


  {                   // one HTTP request
    val a    = Arena()
    val hdr  = a.alloc(...)
    val body = a.alloc(...)
    respond(hdr, body)
  }                   // !!deallocated here!!
  

  val register = {
    val pool = Arena()
    (cb) => pool.alloc(cb)
  }                   // !!pool escapes!!

  register(onClick)   // still allocating
Lexical: deallocated at scope exit. a stack discipline, so nothing inside may escape
Non-lexical: it may escape the block. but its reclamation is left to garbage collection

Our Goal

Classic regions tie lifetime to grouping: a region’s lifetime is its lexical scope.
We decouple grouping from lifetime:
Arenas group resources, even those that outlive their scope
Flexible lifetimes lexical or non-lexical, even for a single reference
In any combination:
One reference type the same Ref[T]
Higher-order code closures, aliases, and shared mutable state
No use-after-free ruled out statically
Reachability Types already achieve part of this goal.

Reachability Types: What Can This Value Reach?

A value of type T??~{q}?? may reach the resources in ??q??, including via aliases and closures. 

  val r = new Ref(8)  //: Ref[Int]??~{r}??
  val x = r           //: Ref[Int]??~{x}?? <: Ref[Int]??~{r}??
  val f = () => !r    //: (() -> Int)??~{r}??
Qualifiers enable reasoning about controlled sharing and separation. 

  val y = new Ref(9)      //: Ref[Int]??~{y}??
  def g(z: Ref[Int]??~{~*r}??) = !r + !y + !z
                          //: ((z: Ref[Int]??~{~*r}??) -> Int)??~{r, y}??
  g(x)                    // ok: sharing r is allowed
  g(!!y!!)                    // !!error:!! g already observes y
The reachability graph is a DAG.
