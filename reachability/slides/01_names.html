Nested References

A reference's qualifier tracks only its immediate reachability, not its referent's. 

  val inner  = new Ref(0)       //: Ref[Int]??~{inner}??
  val outer1 = new Ref(inner)   //: Ref[Ref[Int]??~{inner}??]??~{outer1}??
  val outer2 = new Ref(inner)   //: Ref[Ref[Int]??~{inner}??]??~{outer2}??
  !outer1                       //: Ref[Int]??~{inner}??
!outer1 recovers exactly the referent's reachability.
Two references holding inner stay separate: ??{outer1}?? and ??{outer2}?? are disjoint.

Cyclic References

\u??z??.Ref[T??~{z}??]
The binder ??z?? names the reference in its own type, so its referent may reach it.
Landin's knot: recursion through the store, with no built-in fixed point. → OOPSLA'25 

  val c = new Ref((x: Int) => x)   //: \uz.Ref[(Int -> Int)??~{z}??]??~{c}??
  c := (x: Int) => (!c)(x)         // ok: the function reaches c, and z stands for c
Without cyclic references, every well-typed program terminates.

Cycles Across Arenas

Coarse-grained reachability tracking: an arena's cells are tracked by the arena. 

  val a = new Ref(..)     //: Top??~{a}??
  val b = new Ref(a)      //: Ref[Top??~{a}??]??~{b}??
  val c = new Ref(b) at a //: Ref[Top??~{b}??]??~{c}?? <: Top??~{a}??
      

  b := c                  // ok: closes the cycle
A cell may reach later cells, if they join an arena already reached.
