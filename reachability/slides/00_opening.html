Objects and Ownership

Goal: memory safety, no data races, and timely reclamation, guaranteed statically.
Rust achieves this with ownership: methods borrow or consume the object. 

  struct Counter { c: i32 }
  impl Counter {
      fn incr(&mut self) { self.c += 1 }
      fn decr(&mut self) { self.c -= 1 }
      fn kill(self) {}
  }
  let mut ctr = Counter { c: 0 };
  ctr.incr(); ctr.decr();
  ctr.kill();
  !!ctr.incr()!!;   // !!error:!! ctr was moved
kill consumes ctr, so using it afterwards is rejected statically.

Objects Are Higher-Order

Methods become closures over the object's state. 

  fn counter(n: i32) -> (impl FnMut(), impl FnMut()) {
      let mut c = n;
      (|| c += 1,
       || c -= 1)
  }
  let (mut incr, mut decr) = counter(0);
      

  fn counter(n: i32) -> (impl FnMut(), impl FnMut()) {
      let mut c = n;
      (|| c += 1,
       !!|| c -= 1!!)   // !!error:!! c already borrowed
  }
  let (mut incr, mut decr) = counter(0);
No object owns c: only the two closures reach it.
Shared XOR mutable rejects decr: a closure borrows c when it is created.

Sharing by Reference Counting

Rust's workaround shares the cell through Rc<RefCell<i32>>. 

  fn counter(n: i32) -> (impl FnMut(), impl FnMut()) {
      let c = Rc::new(RefCell::new(n));
      let d = c.clone();
      (move || *c.borrow_mut() += 1,
       move || *d.borrow_mut() -= 1)
  }
  let (mut incr, mut decr) = counter(0);
  incr(); decr();   // incr, decr : impl FnMut()
  !!thread::spawn(incr)!!;   // !!error:!! Rc is not Send
Thread-safe, but only because Rc can never leave its thread.
We cannot reason about sharing and separation from the types.

From Ownership to Reachability

Our goal: the same guarantees in higher-order code, with mutable sharing allowed. 

  def counter(n: Int) = {    // T = Unit -> Unit
    val c = new Ref(n)
    (() => c := !c + 1, () => c := !c - 1)
  }
  val ctr = counter(0)
  val (incr, decr) = ctr     //: incr, decr : T??~{ctr}??
  incr(); decr()             // ok
  par { incr() } { !!decr()!! }  // !!error:!! both reach ??ctr??
Reachability types track what each term may reach, instead of restricting the heap.
c is gone, but the types keep the sharing: both closures carry ??{ctr}??.

Reachability Types

Reachability types track resources in higher-order programs.
We annotate each type with a qualifier, T??~{q}??, what the value may reach. 

  val rx = new Ref(42)   //: Ref[Int]??~{rx}??
         ==> ℓ₁
  val ry = new Ref(7)    //: Ref[Int]??~{ry}??
         ==> ℓ₂
  if (cond) rx else ry   //: Ref[Int]??~{rx,ry}??
Qualifiers over-approximate run-time locations.
